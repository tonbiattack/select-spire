# SELECT Spire 仕様書（SPEC）

作成日: 2026-11-16 / ステータス: 仕様段階

## 概要

Slay the Spire × SQL のデッキ構築ローグライク。

カードがSQL句。カードを組み立ててクエリを1本作ることが、そのまま攻撃になる。敵はテーブル、スキーマは最初は一部しか見えないため、偵察して弱点を読む。

## 共通前提
- プレイヤーが書けるのは原則 `SELECT` のみ。DBは読み取り専用接続で開く
- 実行制限: 1クエリ 100ms / 取得上限 100行（案ごとに調整可）
- 1プレイ完結型。セーブはラン単位のみ
- オンライン対戦・ランキングはMVP外
## 数値仕様
- 1ラン: 15分想定、全8フロア＋ボス（MVPは分岐なしの直線マップ）
- プレイヤーHP: 50
- 1ターン: エネルギー3、手札5枚、初期デッキ12枚

## ダメージ式
- 基本: `min(返却行数, 20) + ボーナス`
- 弱点列を `WHERE` で当てる: ×2
- `JOIN` 成功: +5（コンボ）
- `GROUP BY`: 敵が複数体のときのみ全体攻撃化

## カード例
| カード | コスト | 効果 |
|---|---|---|
| WHERE col =? | 1 | 弱点指定でクリティカル |
| JOIN | 2 | 結合キー判明時にコンボ+5 |
| LIMITで偵察 | 0 | スキーマ1列を公開、ダメージ0 |

## 敵（テーブル）
- スキーマは列名の半分だけ公開された状態で出現する
- `information_schema` 相当の表示が松明（偵察手段）

## 報酬
- フロアごとに3択: カード1枚追加 or インデックス取得
- インデックスはレリック扱い（特定句のコスト-1 など）

## 勝敗条件
- 勝利: ボス撃破
- 敗北: HP 0
- スコア: 残HP ＋ 使用ターン数（小さいほど良い／要確定）

## MVPで作らないもの
- 自由入力モード（最初はカード組み立て式のみ。自由にSQLを書かせると判定が壊れる）
- 分岐マップ、オンライン要素、ランキング
