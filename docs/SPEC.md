# SELECT Spire MVP仕様

更新日: 2026-11-18

## 面白さの核

**隠れた弱点を偵察し、限られた手札とエネルギーでSQLを組み立てて、複数の敵を捌く。** どの句を使うかで「誰に当たるか」が変わる。単体を落とすか、全体を削るか、弱った敵に集中するかを、手札と敵の予告を見て選ぶ。SQL初心者も画面の案内に沿って最初の戦闘から試せるようにする。

## 基盤と範囲

- Python 3.11以上、標準ライブラリの `sqlite3`、Tkinterによる簡易GUIとCLI。追加依存なし。
- ブラウザ版はTypeScriptで同じルールを実装し、GitHub Pagesで公開する。
- 1ランは8フロアとボスの全9戦、直線進行。1戦の敵は1〜3体。
- 自由SQL入力、分岐、オンライン、ランキング、イラスト・アニメーション、音声は対象外。
- ランの永続化・中断再開とスコアはMVP後に先送り。終了時は破棄し、勝敗・残HP・使用ターン数を結果として表示する。
- 実行可能なのはゲームがカードから生成したSELECTのみ。DBを読み取り専用で開き、SQLite authorizerとquery_onlyでも書き込みを拒否する。敵の反撃によるDB更新はゲームが別接続で行う。
- 1クエリ100ms、取得上限100行。超過やSQLエラーは安全に失敗として返し、カードを消費しない。SQLite進捗ハンドラによる時間制限は協調的で、OSのI/OやSQLiteの長時間ネイティブ関数の強制中断は保証しない。攻撃クエリは集計後の行数が小さいため上限に達しない。

## データ構造

- 敵はそれぞれ専用テーブルを持ち、列は `id`、`element`、`armor`、`status` の4つ。
- フロアごとに `battle_<n>` ビューを作り、そのフロアの敵テーブルを `enemy` 列付きで UNION ALL する。攻撃はこのビューへの1本のSELECT。
- 行IDは敵ごとに1000刻みでずらし、UNION しても衝突しない。`support` テーブルは全行IDを網羅するため JOIN は必ず1行に一致する。
- 弱点列には初期行の80%（切り捨て）が `weak` を含み、他の列は含まない。

## ランとターン

- 初期【プレイヤーHP】50、各ターン【エネルギー】3、【手札】5枚。初期デッキはWHERE 4、JOIN 2、偵察 3、GROUP BY 1、ORDER BY 1、LIMIT 1の計12枚。
- 各フロア開始時にデッキをシャッフル。各ターン手札を5枚まで補充し、山札が尽きたら捨て札をシャッフルする。終了時に残り手札を捨てる。
- 攻撃は1ターン1回、偵察は攻撃前後に可能。ターン終了時は生存している全敵の攻撃力の合計ダメージを受け、HPが残れば各敵の特性が発動する。倒した敵は反撃しない。
- 敵テーブルの4列のうち、開始時はidと他の1列を公開。偵察は隠れた列を1つ公開して弱点かも判定する。WHEREで攻撃した列も弱点か判明する。隠された列は再公開するまで使えない。
- 倒すたびにカード追加2択とインデックス1択から報酬を選ぶ。インデックスはWHERE、JOIN、GROUP BY、ORDER BY、LIMITのいずれか1種のコストを1減らす（下限0）。全種を取得済みなら3択目もカードになる。

## SQLとダメージ

各句は「誰に当たるか」を変える。ダメージは1本のSELECTの結果から敵ごとのヒット数を取り、句の役割を適用して決める。

| 操作 | コスト | 役割 |
|---|---:|---|
| 基本SELECT | 0 | 先頭の敵だけを攻撃。いずれかのデータ列がNULLの行は除外 |
| WHERE 列 = 'weak' | 1 | 指定列が `weak` の行だけを抽出。弱点の敵には2倍 |
| JOIN support | 2 | ダメージ+3。加えて隠れた列を1つ公開する |
| GROUP BY | 1 | 全敵を集計し、全員に最低4ダメージ。散った敵をまとめて削る |
| ORDER BY | 1 | ダメージを最も弱った敵1体に集中させる |
| LIMIT 1 | 1 | 最多ヒットの敵1体だけに+8ダメージ |
| LIMIT 偵察 | 0 | 単独で使い1列を公開、ダメージ0 |

句は各種類1枚まで。組み合わせのコストがエネルギー以内であること。WHEREの値は固定の `weak` でパラメータとして渡す。

【ダメージ】は敵ごとに `min(ヒット数, 20) × 弱点倍率` を求め、JOINの+3、GROUP BYの最低4、LIMITの+8、ORDER BYの集中を順に適用する。弱点倍率はWHEREで弱点列を指定した場合2、それ以外1。

## 敵と勝敗

- 全敵に弱点列が必ず1つある。反撃は敵ごとに「公開列を隠す」「弱点以外の列にNULL混入」「4行追加」のいずれか。NULLは通常スキャンの対象行を減らす。追加行は弱点を持つ。
- 全敵撃破で勝利、HP 0で敗北。8階後のボスを倒すと勝利。
- 想定プレイ時間は1ラン約15分。人間による所要時間の実測は未実施で、バランスと所要時間は継続検証する。
- 開発時の自動対戦（固定seed 0〜59、偵察後に弱点狙い／全体攻撃の2戦略、報酬は3番を選択）では両戦略とも60戦60勝、平均約23ターン、平均残HP約21。カードを使わない素手戦略は60戦1勝。人間の勝率を示すものではなく、難易度の参考値とする。

## 旧仕様との差分

- 敵は1フロア1体から1〜3体になった。反撃は生存敵の合計。
- ダメージは「返却行数」から「敵ごとのヒット数」に変わった。基本攻撃は先頭の敵のみ。
- GROUP BYは固定+3から全体攻撃に、JOINは+5から+3＋情報公開に、ORDER BYとLIMITは新規カードとして追加。
- 初期デッキは12枚のまま、内訳を変更した。
- CLIとTkinter版は同じ `Game` API を使うため、両方とも新仕様で動作する。旧仕様の互換モードは設けない。
