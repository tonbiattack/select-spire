# SELECT Spire MVP仕様

更新日: 2026-11-16

## 面白さの核

**隠れた弱点を偵察し、限られた手札とエネルギーでSQLを組み立てて、危険な敵を一気に倒す。** 手札と反撃の予告を見て、安定した通常スキャンと、外す危険があるが強い弱点攻撃を選ぶ。SQL初心者も画面の案内に沿って最初の戦闘から試せるようにする。

## 基盤と範囲

- Python 3.11以上、標準ライブラリの `sqlite3`、Tkinterによる簡易GUIとCLI。追加依存なし。
- 1ランは8フロアとボスの全9戦、直線進行。敵は1戦につき1体。
- 自由SQL入力、分岐、オンライン、ランキング、イラスト・アニメーション、音声、複数敵は対象外。
- ランの永続化・中断再開とスコアはMVP後に先送り。終了時は破棄し、勝敗・残HP・使用ターン数を結果として表示する。
- 実行可能なのはゲームがカードから生成したSELECTのみ。DBを読み取り専用で開き、SQLite authorizerとquery_onlyでも書き込みを拒否する。敵の反撃によるDB更新はゲームが別接続で行う。
- 1クエリ100ms、取得上限100行。超過やSQLエラーは安全に失敗として返し、カードを消費しない。SQLite進捗ハンドラによる時間制限は協調的で、OSのI/OやSQLiteの長時間ネイティブ関数の強制中断は保証しない。攻撃クエリにはLIMIT 100を付ける。

## ランとターン

- 初期【プレイヤーHP】50、各ターン【エネルギー】3、【手札】5枚。初期デッキはWHERE 5、JOIN 3、偵察 3、GROUP BY 1の計12枚。
- 各フロア開始時にデッキをシャッフル。各ターン手札を5枚まで補充し、山札が尽きたら捨て札をシャッフルする。終了時に残り手札を捨てる。
- 攻撃は1ターン1回、偵察は攻撃前後に可能。ターン終了時は敵の予告どおりダメージを受け、HPが残れば敵の特性が発動する。倒した敵は反撃しない。
- 敵テーブルの4列（id、element、armor、status）のうち、開始時はidと他の1列を公開。偵察はLIMITクエリを実行し隠れた列を1つ公開して弱点かも判定する。WHEREで攻撃した列も弱点か判明する。隠された列は再公開するまで使えない。
- 倒すたびにカード追加2択とインデックス1択から報酬を選ぶ。インデックスはWHERE、JOIN、GROUP BYのいずれか1種のコストを1減らす（下限0）。全種を取得済みなら3択目もカードになる。

## SQLとダメージ

| 操作 | コスト | 効果 |
|---|---:|---|
| 基本SELECT | 0 | カードなしで攻撃。いずれかのデータ列がNULLの行を除外 |
| WHERE 列 = 'weak' | 1 | 公開列を1つ指定。該当行を抽出し、列が弱点ならクリティカル |
| JOIN support | 2 | idを結合してダメージ+5 |
| GROUP BY | 1 | idで集計してダメージ+3。複数敵はMVP外のため全体攻撃なし |
| LIMIT 偵察 | 0 | 単独で使い1列を公開、ダメージ0 |

句は各種類1枚まで。組み合わせのコストがエネルギー以内であること。WHEREの値は固定の `weak` でパラメータとして渡す。

【ダメージ】は `(min(返却行数, 20) + JOINボーナス + GROUP BYボーナス) × 弱点倍率`。倍率はWHEREで弱点列を指定した場合2、それ以外1。弱点列には初期行の80%（切り捨て）が `weak` を含み、他の列は含まない。

## 敵と勝敗

- 全敵に弱点列が必ず1つある。反撃は敵ごとに「公開列を隠す」「弱点以外の列にNULL混入」「4行追加」のいずれか。NULLは通常スキャンの対象行を減らす。追加行は弱点を持つ。
- 全敵撃破で勝利、HP 0で敗北。8階後のボスを倒すと勝利。
- 想定プレイ時間は1ラン約15分。人間による所要時間の実測は未実施で、バランスと所要時間は継続検証する。
- 開発時の自動対戦（固定seed 0〜99、偵察後に判明済み弱点とJOIN/GROUPを優先、報酬は3番を選択）では100戦100勝、平均17.07ターン、平均残HP 23.73。カードを使わない戦略は100戦0勝。人間の勝率を示すものではなく、難易度の参考値とする。
